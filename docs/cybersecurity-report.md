## Executive Summary

The Flutter scaffold introduces pinned Dart package versions in `pubspec.lock`, Android Gradle build tooling, and a local signing placeholder. The app declares two Android permissions in the main manifest: `RECORD_AUDIO` and `INTERNET`. `RECORD_AUDIO` is requested at runtime through app-owned native Android code before opening the live-session surface. `INTERNET` supports the app's only routine network path, direct phone-to-OpenAI HTTPS/WebSocket calls, and is declared in the main manifest so it is present in release/store builds rather than only in the Flutter debug/profile manifest overlay (#41). Least privilege for the MVP is exactly `RECORD_AUDIO` + `INTERNET`, plus the AndroidX self-scoped `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` generated into built APKs. Android microphone capture now uses app-owned `AudioRecord` platform code, not a new package dependency, to emit 24 kHz mono PCM16 chunks through a Flutter EventChannel after runtime permission is granted. Android translated-audio output now uses an app-owned MethodChannel and `AudioTrack` stream-mode playback, also without adding a package dependency or Android permission; decoded PCM16 output chunks stay in a bounded transient queue and are not logged or persisted. The storage implementation adds `flutter_secure_storage` for encrypted local meeting, transcript/history, summary text/metadata, generated export bodies, recent language route, recipient preference, sensitive preference, and credential/session material storage. Android app backup is disabled in the manifest for the MVP data boundary. Language support now uses a local conservative realtime-target table and marks broader targets as direct-OpenAI fallback credential routes. OpenAI setup now stores/removes user-provided credential material only through encrypted local storage and does not redisplay the saved value. Direct realtime scaffolding now builds tested WebSocket session messages for the dedicated `gpt-realtime-translate` live profile and explicit compatibility `gpt-realtime-2` profile, keeps credentials in the Authorization header only, waits for `session.updated` or sanitized startup errors before microphone capture starts, parses audio/transcript/error/segment events without logging payloads, classifies direct credential/session expiry or rejection, unsupported-language, retryable network/socket, rate-limit, transient OpenAI, lifecycle-interruption, and fatal failures, and schedules bounded jittered reconnect attempts. The Flutter home surface now listens to asynchronous session-state changes, so live-session failures become visible after the live screen is mounted. `reconnecting`, `offline`, and `error` render a local recovery banner with retry/back controls where appropriate, unsupported-language errors render a language-specific banner without a retry loop, rate-limit and transient-OpenAI errors render sanitized category-specific labels without raw server error details, and `credentialInvalid` renders the OpenAI setup-required screen without displaying credential material. The realtime coordinator reads the encrypted credential before requesting microphone permission, opens realtime before capture, streams PCM16 chunks directly to OpenAI, decodes translated-audio deltas into a fakeable local PCM16 playback gateway, sends production Android playback chunks to native output, upserts parsed transcript deltas into encrypted local meeting storage without logging transcript text, closes capture/realtime/playback resources while the session is reconnecting, offline, credential-invalid, backgrounded, stopped, or the active meeting is deleted, preserves active transcript rows across fake retryable reconnects, clears stale playback chunks before recovered playback, preserves only sanitized realtime failure categories for UI state, and marks partial rows interrupted if retries exhaust. ## MVP Security Posture

- Phone-only MVP aside from direct OpenAI API calls.
- No AWS, Lambda, token broker, app backend, cloud sync, server mailer, or server-side transcript handling.
- Android runtime microphone permission is gated before live translation surfaces; Android microphone capture opens only after encrypted credential and permission gates pass.
- Local encrypted storage now exists for meetings, transcripts, summaries, recipient preferences, sensitive preferences, and future credential/session material through `flutter_secure_storage`.
- OpenAI setup gates live-session start before microphone permission, stores credential material only in encrypted local storage, and supports reset/removal.
- Direct realtime scaffolding keeps credential material in the WebSocket Authorization header only, has no app-owned backend route, and has tests asserting the credential is absent from session update/audio/close message bodies.
- The 2026-06-01 dedicated-translation session-config fix adds `audio.input.transcription` (`gpt-realtime-whisper`) and `audio.input.noise_reduction` (`near_field`) to the session.update body so OpenAI streams the source transcript. It changes only the request body sent on the existing direct phone-to-OpenAI WebSocket; it adds no new network path, no backend, no new permission, and no credential or transcript/audio payload to logs. The connect test asserts the credential stays out of the session body, and diagnostics still record only sanitized operation/profile/target labels.
- The 2026-06-03 fallback-only target routing fix keeps broader targets such as Arabic on the phone-only direct OpenAI fallback path. When the selected target is not a realtime output language, the primary realtime session outputs the realtime-capable language on the other side of the pair instead of sending an unsupported output target, and the fallback-only direction uses the existing direct OpenAI text interpreter with `store: false`. This adds no dependency, Android permission, backend route, credential handling, microphone recording, transcript/audio logging, or diagnostics payload surface.
- The 2026-06-01 round-3 live-source-detection fix changes block-boundary timing in the committer and adds content-free realtime transcript signal telemetry. The new diagnostic event `live_realtime.translation_without_source` and its presence-only keys (`hasSourceSignal`, `hasOutputSignal`, `sourceTurnCount`, `outputTurnCount`, `sourcelessFinalCount`, `signalState`) carry only booleans/counts and a fixed state token — never transcript or translation content. They are added to the `PrivacySafeDiagnostics` allowlist, and a test asserts these keys pass through while transcript-bearing keys stay redacted. The hardened live smoke counts source vs output transcript events but still prints only counts and allowlisted model/path metadata. No dependency, permission, backend route, network path, OpenAI request format, live credential read, or microphone recording changed.
- Release-artifact hardening (2026-06-01): the debug-signed release APK is not distributed for installed device testing; the artifact builder and `scripts/check_apk_metadata.sh` print tester guidance steering testers to the debug APK. This is packaging/messaging only and changes no permission, signing material, or network behavior; store-ready signing enforcement remains in `scripts/check_android_release_signing.sh`.
- Android PCM16 capture uses `AudioRecord` through app-owned platform code and adds no package dependency beyond the existing Android SDK/Flutter platform-channel surface.
- Translated audio deltas are decoded into a fakeable local PCM16 playback gateway only after credential, permission, and realtime gates pass; production Android output uses app-owned `AudioTrack` with a bounded transient queue, does not persist audio-derived data, and logs only sanitized state labels.
- Direct realtime resilience scaffolding classifies failure categories, schedules bounded backoff/jitter reconnect attempts, drives fail-closed session states, and logs only sanitized operation/result/error-code/retry/backoff fields.
- User-visible realtime recovery UI renders only sanitized state/notice text for reconnecting, offline, stopped, unsupported-language, rate-limit, and transient-OpenAI sessions. It adds no network path, no raw server-error display, and no credential display.
- Scoped AI chat keeps prompt/request context local until a user sends it directly to OpenAI from the phone; request construction sets `store: false` and never routes through an app backend.
- Local diagnostics are no-op by default and must pass through field allowlisting, secret redaction, and payload omission before any sink records them.
- Transcript, Summary, and Both export generation is user initiated, runs in the background from the UI perspective, and saves generated export bodies only in encrypted local meeting storage. Recipient input/checklist UI is disabled in the active MVP flow. Generated summary text/metadata remain in encrypted local storage. Summary/Both uses the direct OpenAI Responses path only when a saved local credential is available. Plaintext export bodies are exposed only in the in-app generated export detail view and the explicit Copy action.
- Direct OpenAI API calls are the only routine product network path.
- Generated export copy is user initiated; no app-operated outbound mail backend or external delivery path is active in the MVP.
- Logs, analytics, crash reports, screenshots, diagnostics, and tests must exclude transcript, audio, prompt, summary, recipient, export, and OpenAI credential/session payloads.

## Dependency And Supply-Chain Notes

- `android/key.properties.example` contains placeholders only and points `storeFile` at an absolute out-of-repo placeholder path.
- `android/key.properties` is ignored and must remain local/uncommitted.
- `scripts/check_android_release_signing.sh` is the store-ready signing preflight. It validates local signing fields and keystore path without printing signing material, and `--apk` rejects Android debug-signed artifacts.
- `scripts/final_qa_gate.sh --require-store-signing` runs the store-signing preflight before the release build and verifies the fresh release APK is not debug-signed afterward. Normal final QA remains available for non-store QA/handoff without signing material.
- Release-mode APK artifacts built without local `android/key.properties` use the existing debug-signing fallback and are labeled `release-debug-signed`; they are suitable only for local handoff/smoke validation, not production store submission.
- No standard OpenAI API key, client secret, token broker URL, AWS config, Google/Microsoft sign-in config, keystore, or certificate has been added.
- The Flutter scaffold includes Android and iOS platform code only; there is no app-owned network endpoint.
- Microphone permission, Android PCM16 capture, and Android PCM16 translated-audio output use app-owned platform code and do not add a supply-chain dependency. Translated-audio playback uses platform `AudioTrack` and adds no package, SDK, or additional permission. Capture/playback should be reviewed again if a package, SDK, resampler, external playback engine, or additional audio permission is introduced.
- Encrypted local storage uses `flutter_secure_storage` 10.3.0. Android storage is backed by Android KeyStore/Tink through the plugin; iOS storage is backed by Keychain with `first_unlock_this_device` accessibility.
- Android backup is disabled for the app manifest to avoid backup/restore copying secure-storage ciphertext outside the phone-only MVP boundary.
- `scripts/check-supply-chain.sh` is now the required local supply-chain gate. It fails on obvious OpenAI/AWS/private-key secret patterns, unexpected Android permissions, a source main manifest missing the required `RECORD_AUDIO`/`INTERNET` permissions, OSV query errors, or OSV vulnerabilities in pinned hosted Pub and Gradle/Maven package versions.
- CI now runs docs validation plus Flutter analysis/tests and the supply-chain gate on pull requests and pushes to `main`. Emulator smoke remains a local/manual gate through `android-pixel9-headless`; the #39 release smoke and its resilient cold boot are local-only by design and were not added to CI.
- `scripts/android_release_smoke.sh` can optionally post a result block to a GitHub release (`--record-to-release`) or issue (`--record-to-issue`) through the local `gh` CLI. Posting is opt-in and runs a secret-pattern scan before any network call. The block contains only APK SHA-256/package/version/permission/signing/device facts and per-check status, never credential, transcript, prompt, summary, or export payloads. The default behavior prints the block locally and makes no network call.
- Language fallback routing, OpenAI credential setup, direct realtime WebSocket/resilience/coordinator scaffolding, Android PCM16 capture, Android PCM16 translated-audio playback, privacy-safe diagnostics, AI chat request scaffolding, direct summary request scaffolding, and transcript/summary export handoff do not introduce dependencies. Unsupported realtime targets are marked as requiring the phone-only direct OpenAI fallback credential path, with no AWS, app backend, cloud sync, or server-side transcript path.
- The generated-spoken-audio and controlled reconnect smokes use the host OS `espeak-ng` executable only when the optional live smoke runs. It is not a Flutter/mobile dependency, is not bundled in the app, and no generated audio fixture is committed.
- The current storage repository writes one encrypted local document. Large long-running transcript volume should be reassessed before production-scale retention or import/export features expand beyond the MVP test data shape.
- Future dependency additions must include lockfile updates, advisory checks, and this report update before issue closure.

## MVP Cybersecurity Acceptance Criteria

- No committed or bundled standard OpenAI API key.
- No app backend or server-side transcript handling.
- Direct OpenAI API only for routine product network traffic.
- Encrypted local storage for meetings, transcripts, summaries, recipients, sensitive preferences, and credential/session material.
- Explicit AI chat scope: `This meeting` or `All meetings`.
- Generated exports avoid an app-operated outbound mail backend and remain encrypted locally until explicit Copy.
- Mobile permissions are minimized and justified.
- Dependency versions are pinned and checked before merge once implementation exists.
- Logs, analytics, crash reports, screenshots, diagnostics, and tests exclude sensitive content.
- App diagnostics use an allowlist/redaction helper and must not record transcript, audio, prompt, summary, recipient, export, credential, token, or raw request/response payloads.

## Open Security Risks To Resolve During Implementation

- User-provided OpenAI credential/session material in a mobile app is accepted for MVP only because Tom chose a phone-local no-backend path. Implementation must minimize exposure with encrypted local storage, no logging/screenshots/test output, and a clear reset/removal path.
- Direct realtime endpoint creation now works for both configured profiles, Android PCM16 capture is wired locally, and translated-audio deltas can enter Android `AudioTrack` output through the fakeable local playback gateway. Normal MVP live interpretation now uses the dedicated `gpt-realtime-translate` profile; remaining live-audio risk is real physical microphone translation, committed live transcript validation from the installed app, and audible speaker output/recovery under live streaming.
- Native secure-storage behavior should be smoke-tested on real Android and iOS devices before production release, especially for long transcript volume and backup/restore edge cases.
- Any crash reporting or analytics SDK should be deferred unless a strong need and redaction/consent model are documented.
- Native email/share composer behavior must continue to be tested as export features expand, especially once iOS share handoff is validated.
- Direct realtime scaffolding still needs audible translated-audio recovery under live streaming, live committed transcript delta validation from the installed app, credential-expiry validation, real microphone translation smoke, and live app-coordinator transcript de-duplication validation before #6/#14 can close.
